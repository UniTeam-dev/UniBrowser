# «Через Mac»: прямое подключение по внешнему адресу и свой сервер связи — план

Спека: `docs/superpowers/specs/2026-10-19-via-mac-direct-and-relay-design.md`.

1. `Shared/ViaMac/ViaMacAddress.swift` (чистая логика, проверка
   `scripts/via_mac_address_check.swift`): разбор «host[:port]» (IPv4, имя, `[v6]:port`),
   распознавание серверов n0 (`*.iroh.link`) и проверка URL своего сервера.
2. Протокол: `PairingPayload.externalAddress`, `ControlResponse.relayURL/externalAddress`,
   `ControlRequest.ping(path:)` — путь, которым телефон связан с Mac. Старые версии
   декодируют новые сообщения (проверяется в том же скрипте).
3. Mac: настройки «Порт», «Внешний адрес», «Свой сервер связи» (UserDefaults);
   endpoint на `0.0.0.0:<порт>` (IPv6 остаётся на случайном порту iroh), при занятом
   порте — случайный порт и предупреждение; `RelayMode.customFromUrls` для своего
   сервера; секция «Подключение из других сетей» в окне iPhone и в Настройках → iPhone:
   адрес Mac в локальной сети, порт для проброса, путь последнего подключения телефона.
4. iPhone: внешний адрес и сервер связи приходят в QR и в каждом ответе Mac;
   переопределения в «Подключение»; имя разрешается перед каждым подключением
   (getaddrinfo); свой сервер → endpoint телефона с тем же `RelayMode`, перепривязка
   при смене; статус «Напрямую через внешний адрес» / «Напрямую» / «Через сервер связи».
5. Документы: `docs/via-mac-direct.md`, `docs/via-mac-relay.md` и файлы
   `docs/via-mac-relay/` (конфиг iroh-relay, systemd, nginx stream SNI, docker compose) —
   ключи сверены с исходниками iroh-relay 1.0.2.
6. Проверка: сборки обоих приложений, `merge_check`, новая проверка; симулятор +
   изолированная копия Mac: (A) внешний адрес = LAN IP:порт и имя `.local`, серверы связи
   отключены; (B) локальный `iroh-relay --dev` в Docker, прямые пути заблокированы
   временной тестовой привязкой сокетов Mac; замеры времени и ресурсов контейнера.
