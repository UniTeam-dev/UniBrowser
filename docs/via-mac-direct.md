# «Через Mac»: прямое подключение по внешнему адресу

Когда iPhone в мобильном интернете, а Mac дома, связь по умолчанию идёт через публичные
серверы связи iroh (n0). Некоторые сети тормозят такие соединения: первая страница может
ждать 30–80 с. Если у дома белый (публичный) IP, телефон может подключаться к Mac
напрямую — через проброшенный на роутере UDP-порт. Это быстрее и не зависит от чужих
серверов.

Что нужно: белый IP (или IPv6, см. ниже), проброс UDP-порта на Mac, постоянный адрес Mac
в домашней сети и — если IP меняется — имя DDNS.

## 1. Белый ли у вас IP

1. Откройте веб-интерфейс роутера и найдите внешний адрес (WAN, «Интернет», «IP-адрес
   провайдера»).
2. Откройте с домашней сети [2ip.ru](https://2ip.ru) (или любой «мой IP»).
3. Адреса совпадают — IP белый. Не совпадают, или WAN-адрес из диапазонов `10.*`,
   `172.16–31.*`, `192.168.*`, `100.64–127.*` — провайдер выдаёт серый адрес (NAT
   провайдера), пробросить порт не получится. Белый IP обычно подключается у провайдера
   отдельной услугой. Без него остаётся свой сервер связи: `docs/via-mac-relay.md`.

Белый IP бывает динамическим (меняется при переподключении) — тогда нужен DDNS (п. 4).

## 2. Порт на Mac

UniBrowser на Mac слушает связь с iPhone на постоянном UDP-порту, по умолчанию **47802**.
Его видно в UniBrowser → Настройки → iPhone (и в окне «iPhone…», ⇧⌘I), в секции
«Подключение из других сетей»:

- «Адрес Mac в локальной сети» — куда пробрасывать (например, `192.168.1.20`);
- «Порт для проброса» — какой порт пробрасывать, протокол **UDP**.

Порт можно сменить там же (Return применяет). Если порт занят другой программой,
UniBrowser сообщит об этом и запустит связь на случайном порту — она будет работать, но
проброс на роутере — нет; выберите другой порт.

Порт постоянный только для IPv4. IPv6-сокет iroh получает случайный порт: в домашних сетях
IPv6 обычно и так доступен напрямую, если роутер разрешает входящие соединения.

## 3. Постоянный адрес Mac в домашней сети

Проброс указывает на конкретный адрес Mac, поэтому он не должен меняться. Закрепите его
на роутере (резервирование DHCP): найдите Mac в списке устройств и выберите «постоянный
IP» / «резервировать адрес». Если Mac подключается и по Wi-Fi, и по кабелю — у этих
подключений разные адреса; закрепите тот, которым Mac пользуется дома постоянно.

## 4. Проброс UDP-порта

Общая схема на любом роутере: раздел «Переадресация портов» / «Port forwarding» /
«Виртуальные серверы» → новое правило: протокол **UDP**, внешний порт **47802**,
внутренний адрес — адрес Mac, внутренний порт **47802**.

Названия пунктов ниже — для типичных прошивок; в вашей версии они могут немного отличаться.

**Keenetic.** «Сетевые правила» → «Переадресация» → «Добавить правило»: вход —
подключение к провайдеру, выход — IP-адрес (адрес Mac), протокол UDP, порт 47802.
Постоянный адрес: «Список устройств» → устройство → «Зарегистрировать» и «Постоянный
IP-адрес».

**TP-Link.** «Дополнительные настройки» → «NAT переадресация» → «Виртуальные серверы» →
«Добавить»: внешний порт 47802, внутренний IP — адрес Mac, внутренний порт 47802,
протокол UDP. Постоянный адрес: «Сеть» → «DHCP-сервер» → «Резервирование адресов».

**ASUS.** «Интернет» → «Переадресация портов» → «Добавить профиль»: внешний порт 47802,
внутренний IP — адрес Mac, внутренний порт 47802, протокол UDP. Постоянный адрес:
«Локальная сеть» → «DHCP-сервер» → «Назначать IP-адреса вручную».

iroh сам тоже пробует открыть порт через UPnP / NAT-PMP / PCP, если роутер это позволяет,
но полагаться на это не стоит — пробросьте вручную.

Если на Mac включён брандмауэр (Системные настройки → Сеть → Брандмауэр) в режиме
«Блокировать все входящие подключения», выключите этот режим или разрешите UniBrowser.

## 5. Внешний адрес: IP или имя DDNS

В UniBrowser → Настройки → iPhone, поле «Внешний адрес», укажите белый IP дома или имя
DDNS; порт через двоеточие нужен, только если внешний порт на роутере отличается от
порта Mac: `203.0.113.7`, `home.example.net`, `home.example.net:50000`. Mac передаёт
его телефону в QR-коде и в каждом ответе, отдельно пересканировать код не нужно.

Если IP меняется, заведите имя DDNS — оно всегда указывает на текущий IP. Телефон
заново узнаёт адрес имени перед каждым подключением.

- **Keenetic:** «Общие настройки» → «Доменное имя KeenDNS» → имя вида `home.keenetic.pro`
  в режиме **«Прямой доступ»** (режим «Через облако» пропускает только веб-страницы и
  для связи с Mac не подходит).
- **TP-Link:** «Дополнительные настройки» → «Сеть» → «Динамический DNS» (TP-Link DDNS,
  No-IP и другие).
- **ASUS:** «Интернет» → «DDNS» (бесплатное имя `*.asuscomm.com`).

## 6. Проверка из мобильного интернета

1. На iPhone выключите Wi-Fi.
2. Откройте UniBrowser, режим «Через Mac». В его настройках «Связь» должна показать
   **«Напрямую через внешний адрес»**. «Через сервер связи» — прямой путь не сработал:
   проверьте проброс, адрес Mac и IP.
3. На Mac в окне «iPhone…» рядом с телефоном показан путь его последнего подключения.

Если адрес, который прислал Mac, устарел (например, Mac давно не был включён), на iPhone в
настройках «Через Mac» → «Подключение» можно указать свой «Внешний адрес Mac»: пустое поле —
как на Mac.

## IPv6

Если провайдер даёт IPv6, iPhone и Mac часто связываются по нему напрямую без проброса,
когда роутер разрешает входящие соединения к устройствам: адреса Mac телефон получает сам.
Порт Mac для IPv6 случайный (см. п. 2), поэтому «Внешний адрес» — для IPv4 с пробросом.
